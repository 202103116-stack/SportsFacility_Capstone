## 1. Problem Definition

**목표**: 시설 특성(업종/시설유형/지역/면적/시설연령)으로 안전위험군을 예측하는
분류 모델 → 예측 위험도 기반 점검자원 우선순위 로직 → 사고통계 교차검증.

**타겟 (EDA로 확정, CLAUDE.md 수정 반영)**:
- ~~3-클래스(주의/사용중지/수리필요)~~ → **이진분류: 양호(0) vs 위험군=주의+사용중지(1)**
  (근거: `사용중지`가 전국 23건뿐이라 별도 클래스 학습 불가 — `docs/eda_findings.md` §2)
- 클래스 비율: 위험군 3.85% → 심각한 불균형, `class_weight`/리샘플링 필수
- 분석 대상: `faci_stat_nm == '정상운영'`으로 한정 권장(폐업 시설은 점검자원 배분 대상 아님)
- 라벨 결측(정상운영 기준 23.3%)은 학습에서 제외

**성공 지표**: Accuracy 지양, Recall/Precision/F1/PR-AUC 우선 (CLAUDE.md 명시). 불균형
이진분류이므로 특히 PR-AUC와 Recall(위험 시설을 놓치지 않는 것)을 핵심 지표로 삼는다.

## 3. Data Quality / Leakage Audit & 예측 범위 설계 (Option A vs B)

`docs/eda_findings.md`, `docs/data_dictionary.md` §4에 정리된 품질 이슈(면적 이상치,
날짜 더미값, 의미불명 코드필드) 외에 **구조적으로 중요한 설계 이슈**가 하나 있다:

> ⚠️ **`TODZ_API_FACI_SAFETY`는 시설당 "가장 최근 점검 결과" 1행만 제공한다.**
> 즉 `schk_visit_ymd`(점검방문일)는 현재 라벨(`schk_tot_grd_nm`)을 만든 바로 그 점검의
> 날짜다. 이걸로 만든 `days_since_inspection`은 "예전 점검 이후 지금까지 얼마나
> 지났나"가 아니라 "그 라벨을 만든 점검이 언제 있었나"에 가깝다 — CLAUDE.md가 원래
> 의도한 "마지막 점검 후 경과일수로 위험도를 예측한다"는 스토리와 미묘하게 어긋난다.

### 용어 정리: "분류"와 "예측"의 두 가지 의미

- **분류(classification)** = 모델이 푸는 문제의 종류(이진분류: 양호=0 vs 위험군=1)
- **예측(prediction)** = 그 분류 모델을 실제 데이터에 적용하는 **행위** 전반
- "예측"이라는 말 안에 다시 두 가지가 섞여 있어 혼동하기 쉽다:
  - **① 추론(inference)**: 정답을 모르는 케이스에 학습된 모델을 적용해 확률을 뽑는 것
    (`model.predict_proba()`). 라벨 없는 33,111건에 점수 매기는 게 정확히 이것.
  - **② 미래예보(forecasting)**: "3개월 뒤 위험해질 것이다"처럼 시간이 지나야 확인되는
    사건을 맞히는 것.
- Option A는 **①**에 해당한다(②는 아님). 의사가 정밀검사 없이 증상만으로 "이 환자는
  특정 질병일 확률이 높다"고 진단 예측하는 것과 같은 구조 — 질병(위험 상태)은 **이미
  존재**하지만 아직 측정(점검)을 안 해서 모를 뿐이다. 이것도 명백히 정당한 "예측"이며,
  신용평가 스코어링·이상거래 탐지 등 실무에서 흔한 형태다. 다만 "미래를 예보한다"는
  과장된 표현은 피할 것 — 정확한 표현은 "위험군일 확률을 추정한다".
- Option B(아래)가 되어야 비로소 **②** 진짜 forecasting이 가능해진다.

### Option A — 현재 채택 (이번 학기 범위)

`TODZ_API_FACI_SAFETY` 단독으로 "시설의 현재 속성이 현재 위험등급과 어떤 연관이
있는가"를 보는 **연관성/추론 모델**. 인과적으로 "미래 위험을 예측"한다고 과장하지
않고, "이런 속성의 시설이 위험군일 가능성이 높다 → 우선 점검 대상으로 스코어링한다"는
정도로 범위를 명확히 좁힌다. (제조/품질관리 유비 — "현재 설비 속성과 현재 불량 여부의
연관성 분석"도 동일 논리로 유효함)

**데이터 흐름**:
```python
labeled = df[df['grade_raw'].notna()]      # 65,440건 → train/test split (학습·검증용)
unlabeled = df[df['grade_raw'].isna()]     # 33,111건 (정상운영 한정 시 16,773건) → 예측 대상(추론용, 2단계 우선순위의 입력)

model.fit(X_train, y_train)
risk_scores = model.predict_proba(unlabeled[features])[:, 1]   # 우선순위는 이 확률로 정렬
```

**train/test 분할 타당성** (확인 완료): 라벨 있는 65,440건(위험군 2,522건) 기준 80/20
stratified split 시 test에 위험군 ≈504건 남음 → Recall/Precision/F1/PR-AUC 추정에
충분. 더 안정적으로는 Stratified 5-Fold CV 권장 (§4에도 반영).

**임계값(threshold) 처리 — 용도별로 다르게**:
- 분류 성능을 지표로 보고할 때: 기본값 0.5는 이 정도 불균형(위험군 3.85%)에서 부적합할
  수 있음 → PR curve로 F1 최대화 지점 등 임계값을 별도로 탐색해야 함 (§7에서 수행)
- 2단계 "점검 우선순위"를 매길 때: **임계값 자체가 불필요**. 확률 0.1짜리 시설도 그보다
  낮은 시설보다는 먼저 점검하면 되므로, 전체를 확률 내림차순 정렬 후 예산/인력이 허용하는
  top-N을 뽑는 방식이 자연스럽다.

**보너스 — Out-of-Time(OOT)/전향적 검증 가능성**: 라벨 없던 33,111건 중 일부는 학기
중 실제로 점검을 받아 라벨이 생길 수 있다. 이때 "모델이 예전에 준 확률과 실제 결과가
맞았는가"를 비교하면 정식 명칭이 있는 검증 기법 — **Out-of-time validation**(금융권
용어) / **prospective validation**(의학 용어)이 된다. 데이터 누수가 원천적으로
불가능한, 회고적 검증(train/test split)보다 오히려 더 엄밀한 방식.
- 실측 확인(2026-09-17 → 09-24, 1주일): 신규 등록 시설 91개 발생, 그러나 라벨 없던
  33,111건 중 **라벨이 새로 생긴 건 0건**. 시설당 평균 점검 간격이 191~253일이라
  전환 속도가 매우 느림 — 표본이 학기 중 수십 건 이상 모이긴 어려울 전망.
- 따라서 정식 지표(Precision/Recall/F1 등, 표본 안정성 필요)로 쓰기보다는, 소수
  사례를 모아 **"사례 기반 검증"**(정성적 부록)으로 발표에 넣는 것을 권장.

### Option B — 진짜 forecasting (향후 확장, 현재 데이터 정합성 미확정)

점검 **이력** 데이터로 시설별 타임라인을 재구성해 "T-1 시점 속성(직전 등급 포함) →
T 시점 등급"을 예측하는 패널 구조. T 시점 결과는 T-1 시점엔 아직 존재하지 않던
정보(평균 191~253일 뒤 결정)이므로, 이건 위 **② 진짜 미래예보**에 해당한다.
검증도 무작위 split이 아니라 **시간 기준 split**(예: T가 특정 날짜 이전인 쌍으로
학습, 이후인 쌍으로 테스트)이어야 "미래를 맞혔다"는 주장이 성립한다.

**⚠️ 1차 조사 수치 (SCHK만 반영 — 과소평가된 것으로 판명, 아래 참고)**:
`TODZ_API_FACI_SCHK`(공식 안전점검 이력, 267,694건) 단독 기준 시설 62,757개,
74.5%(46,784개)가 점검 2회 이상, 전이쌍 192,593개 구성 가능, T시점 위험군 비율
5.87%(11,314건).

**⚠️⚠️ 중요 발견 — 위 수치는 실제보다 축소됐을 가능성이 큼**: SAFETY 테이블에서
라벨 있는 시설 65,440개와 SCHK의 62,757개를 `faci_cd`로 직접 대조하니 **실제
교집합은 8,432개(13%)뿐**이었다. 나머지 57,008개(87%)는 SCHK 이력에 전혀 안 잡힌다.
이 그룹의 `atnm_chk_yn`(자율점검대상여부) 92%가 Y(전체 평균 85.2%보다 높음) —
API 세부기능이 공식점검(`SCHK`)과 **자율점검**(`TODZ_API_FACI_ATNM`, 자율안전점검결과
종합 조회)으로 나뉘어 있는데, 현재 등급의 상당수가 SCHK가 아니라 **ATNM 경로**로
매겨졌을 가능성이 높다.

**다음 단계 (미완료)**: `TODZ_API_FACI_ATNM`(자율점검 이력) 전수 수집 → `faci_cd`
기준으로 SCHK와 병합해 시설별 전체 점검 타임라인(공식+자율) 재구성 → 위 전이쌍
수치를 다시 계산해야 Option B의 진짜 타당성을 확정할 수 있다. **그때까지 위 1차
수치(192,593쌍)는 잠정치로만 취급할 것.**

**리키지 주의(Option B 한정)**: `schk_tot_text_cn`/`schk_refm_text_cn`은 T-1
시점 것만 피처로 사용 가능. T 시점(예측 대상)의 텍스트/결함코드는 라벨과 사실상
동의어이므로 절대 사용 금지.

## 4. Validation Design (구현 완료 — `src/modeling.py`)

- Train/Test 분할: **위험군 라벨 × 점검 트랙(`inspection_track`) 4개 조합으로 층화**.
  라벨만 층화하면 폴드마다 자율점검 트랙 위험군이 153~180건으로 흔들리지만(공식 255~282건),
  조합 층화는 164건/271건으로 고정되어 트랙별 성능 비교가 안정적이다(2026-09-25 확인).
- 교차검증: Stratified K-Fold (k=5), 위 조합을 층화 키로 사용. 인코딩·결측 대체는 fold 안에서만
  학습(Pipeline)해 누수를 막는다.
- 모델 구조: **트랙 구분 없이 단일 통합 모델 1개.** 시군구(`cpb_nm`)를 포함해 3회 반복 비교한 결과,
  트리 모델(HGB)은 분리해도 이득이 미미하고 방향도 엇갈린다(자율 0.121→0.113, 공식 0.500→0.512).
  선형 모델(로지스틱)은 분리하면 공식 트랙이 0.320→0.393으로 오르는데, 가산 모델이 트랙별 상호작용을
  못 잡기 때문이며 트리는 스스로 처리한다. 최종 모델이 트리 계열이므로 통합을 유지하고, 튜닝 단계에서 재검토.
  (주의: 분리 모델의 "전체" PR-AUC는 트랙 간 점수 척도가 달라 통합과 비교할 수 없음)
- 트랙별 보고: 전체 성능과 함께 공식/자율 트랙별 PR-AUC를 반드시 따로 보고한다. 예측 대상의 95%가
  자율 트랙이라 자율 트랙 수치가 실제 적용 성능에 가깝다. 자율 트랙은 기준선(1.9%) 대비 PR-AUC 약 6배,
  상위 10% 점검 시 위험군의 약 49%를 포착한다(로지스틱/HGB 공통, §5 참고).
  (정정: 이전에 적었던 "자율 트랙 변별력 약함(2.4배)"은 시군구를 뺀 진단 모델의 결과였으며 오류.)
- 리키지 주의: `schk_tot_text_cn`(안전점검종합평가내용), `schk_refm_text_cn`(개선방향내용)은
  점검 "결과"이자 라벨과 사실상 동의어이므로 **피처로 절대 사용 금지**
- 지표: PR-AUC(주지표), Recall, Precision, F1 — Accuracy는 참고용으로만 표기
- 분류 임계값(threshold): 기본 0.5 대신 PR curve 기반으로 F1 최대화 지점 등을 §7에서
  탐색(§3 Option A 참고). 2단계 우선순위 스코어링에는 임계값 불필요(확률 순위만 사용)
- 보너스 검증: 학기 중 API 재수집으로 라벨 없던 시설에 라벨이 새로 생기면 OOT/전향적

## 5. Baseline + Preprocessing / Feature Engineering (전처리 완료, 모델링 대기)

**피처 선별 원칙**: "점검을 받기 전에도 관측되는 값인가?" — 예측 대상(라벨 없는 시설)에서 값이 없거나,
점검 과정의 부산물인 컬럼은 학습·평가 어디에도 쓰지 않는다. train/test 피처는 실제 예측 때
쓸 수 있는 피처와 같아야 test 성능이 배포 성능을 대변한다.

| 구분 | 컬럼 |
|---|---|
| **사용** | `fcob_nm`, `ftype_nm`, `cp_nm`, `cpb_nm`(227개 값, 모델링 단계에서 희소값 그룹핑), `faci_gb_nm`, `area_sqm`/`log_area`, `age_years` |
| **평가용 그룹변수** | `inspection_track`(공식/자율) — 피처로 넣지 않고 층화·트랙별 성능 보고에만 사용 |
| **제외** | `schk_visit_ymd`, `schk_open_ymd`, `days_since_inspection`(예측 대상 100% 결측), `faci_upd_ymd`(라벨 유무별 분포 상이: 라벨 있음 63.5%가 2026년 수정 vs 없음 17.4%), `inout_gbn_nm`·`faci_mng_type_cd`(의미 불명 + 라벨 유무별 결측률 차이), 점검 텍스트, 전화·홈페이지 |

- `atnm_chk_yn`은 (시설구분, 업종)으로 100% 결정되는 값이라 정보가 중복이다(넣어도 성능이 오르지 않음 —
  초기 진단 기준, 시군구 제외 모델). 따라서 피처에서 제외한다. 이 때문에 "업종별 위험 차이"와 "점검 방식(공식/자율)
  차이"는 분리할 수 없다 — 논문 한계로 명시.
- 라벨의 대부분(라벨 있는 시설의 약 78%)이 운영자 자체 점검(자율점검) 결과다. 모델이 맞히는 대상은
  "실제 위험"이라기보다 "점검 결과에서 위험(주의/사용중지)으로 판정되는가"에 가깝다 — 논문 한계로 명시.
- **점검 관련 피처를 넣은 모델은 부록 ablation으로만** 고려(배포 불가 명시). 메인 결과에는 사용하지 않는다.
- (참고) "마지막 점검 후 경과일"은 Option A에서 쓸 수 없고, 점검 이력 패널을 쓰는 Option B에서만 가능하다.

**전처리 (`src/preprocess.py`, 스냅샷 `facility_safety_20260917.csv` 고정)**
- 정상운영 시설만 (71,842건 = 라벨 있음 55,069 + 예측 대상 16,773). 위험군 2,175건(3.95%).
- 면적: 날짜(YYYYMMDD)·10억 이상 값(총 5건)과 0 이하만 결측. 골프장·스키장 등 100,000㎡ 초과 대형 시설은 정상값이라 유지(368건).
  `log_area` 함께 제공. (면적 0.0 초과 10㎡ 미만 119건은 유지 — 타당성 확인 필요)
- 시설연령 `age_years`: `base_ymd` 기준. `faci_reg_ymd`는 2016-12-31에 31%가 몰려 있어(일괄 등록일로 추정)
  사용하지 않음. `base_ymd`의 1900-01-01 등 더미값(연도 1950 미만)과 미래 날짜는 결측.
  (등록일 기반 대비 PR-AUC 0.262 vs 0.253, 잡음 범위 — 개념적 타당성으로 선택. 초기 진단, 시군구 제외 모델)
- 결측 대체·인코딩은 전처리에서 하지 않고 모델링 Pipeline(fold 내부)에서 처리. 결측 여부 플래그는 **넣지 않기로 확정**
  (로지스틱 검증 결과 이득 없음: 전체 PR-AUC 0.252 vs 0.253, 두 트랙 모두 동일).
- 산출물: `data/processed/facility_safety_features_20260917.csv`

**베이스라인 결과** (`src/train_baseline.py`, 위험군×트랙 층화 5-fold 3회 반복, OOF 예측 기준. `outputs/reports/baseline_metrics.csv`)

| 모델 | 전체 PR-AUC | 공식 PR-AUC (기준선 11.2%) | 자율 PR-AUC (기준선 1.9%) | 자율 상위10% 포착 |
|---|---|---|---|---|
| 업종(ftype) 위험률 기준선 | 0.151 | 0.206 | 0.025 | 15% |
| 로지스틱(balanced) | 0.253 [0.233, 0.269] | 0.320 | 0.119 [0.102, 0.140] | 49% |
| HGB 기본, 시군구 포함 (1회, 참고) | 0.373 | 0.502 | 0.116 | 49% |

- 로지스틱 대비 트리(HGB)는 전체·공식 트랙에서 크게 앞서지만 **자율 트랙(예측 대상의 95%)에서는 동일**하다(0.116 vs 0.119).
- **시군구(`cpb_nm`)가 결정적 신호**다. 로지스틱에서 시군구를 빼면 자율 트랙 PR-AUC가 0.117→0.045로 무너지고,
  지역만으로도 0.094가 나온다. 반면 업종/시설구분만으로는 0.025(기준선 0.019)에 불과하고, 면적·연령은 거의 기여 없음(0.119→0.117).
- **해석 주의**: 시군구 신호가 "시설 자체의 위험"인지 "지자체별 점검·기재 관행"인지 이 데이터로는 구분할 수 없다.
  HGB에서 규제를 강하게 걸면 오히려 성능이 떨어지는(0.373→0.319) 것도 매우 세밀한 시군구×업종 패턴을 쓴다는 뜻이다.
  → §7에서 시군구 단위 GroupKFold(처음 보는 지역에서도 되는가)와 근접 중복 확인을 반드시 수행하고, 논문 한계로 명시.
- 예정 파일: `src/train.py`(트리 모델)

> 기존 `data/processed/facility_safety_clean_20260917.csv`(EDA 부산물)는 폐기 대상 — 면적 규칙이 대형 시설을
> 결측 처리하고 `days_since_inspection`이 포함되어 있어 모델링에 쓰면 안 된다.

## 6. Modeling & Training (다음 단계)

- **결과(2026-09-25, `outputs/reports/model_metrics.csv`, 상세는 `docs/decision_log.md` D9–D11)**: 실제 적용 조건(같은 지역,
  중첩 튜닝 HGB)에서 자율 트랙 PR-AUC 0.119(기준선 1.9%의 6.2배), 공식 트랙 0.488(4.3배). 자율 트랙에서는 로지스틱과
  동일(0.119)해 복잡한 모델의 이득이 없고, 트리의 이득은 공식 트랙에만 있다. 시설명 중복 누수는 없으나(R3≈R1),
  처음 보는 지역에서는 자율 트랙이 무작위 수준(0.02–0.03)으로 무너진다.
- **시군구 신호는 지자체별 판정 관행이 섞인 것으로 보임**(자율 트랙 시군구 122개 중 위험 판정 0건이 30개, 우연이면 3.6개;
  성남시 1,044곳 중 0건). **결정(D12): C안 — 시군구를 포함한 A를 주 모델로 쓰되 한계를 명시하고, 지역 제외 B는 보조로 보유·병행 보고.**
  B 성능(D13): 공식 트랙 PR-AUC 0.284(무작위의 2.5배), 자율 트랙 0.029(1.5배) — 자율 트랙은 시설 속성만으로 거의 구분되지 않는다.
  A 점수 산출(D14, `src/score_unlabeled.py`): 위험 판정 0건 지역 30곳의 시설 약 1,570곳이 A 상위 10%에서 사실상 제외됨 — 완화 방안 미결정.
- **부스팅 계열 비교(D15, 2026-09-25)**: LightGBM ≈ HGB, CatBoost가 공식 0.520·자율 0.124로 전 그룹 소폭 우세(공식 +0.032, 자율 +0.005는
  신뢰구간이 겹침). 자율 트랙은 4개 모델이 모두 0.12 안팎으로 수렴 — 성능 천장은 모델이 아니라 피처(정보)의 한계. 최종 후보는 CatBoost(잠정).
- 불균형 대응: `class_weight`, `scale_pos_weight`, 또는 SMOTE류 오버샘플링 비교
- 예정 파일: `src/train.py`, `models/`에 저장
